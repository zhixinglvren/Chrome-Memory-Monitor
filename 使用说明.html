Chrome 内存监控工具 - 使用说明

概述

本工具通过 Chrome DevTools Protocol (CDP) 实时采集浏览器的内存与性能数据，支持：

采集策略（双层，各自独立定时器 + 自适应间隔）：
- 分配采样（Allocation Sampling）：类似 Chrome F12 Memory 面板点击"开始录制"，持续录制期间的内存分配信息；到点 stopSampling 保存 profile → 再 startSampling 继续录制，循环往复
- 堆快照（Heap Snapshot）：通过 HeapProfiler.takeHeapSnapshot 按独立频率定期保存完整 V8 堆快照，用于深度分析

核心特性：
- 实时 JS 堆内存监控（仪表盘 + CSV 日志 + Sparkline 趋势曲线）
- DOM 节点数、事件监听器、文档数等详细指标
- 自适应监控间隔（根据内存使用率自动切换正常/高频/紧急模式）
- 分配采样独立开关（sampling-*.heapprofile，可直接在 DevTools 中分析）
- 堆快照独立开关（heap-*.heapsnapshot，内存超阈值时自动触发）
- 浏览器崩溃前自动保存最后采样 + 快照
- 终端可视化仪表盘（实时趋势曲线 + 彩色进度条）
- 通用导航（支持任意 URL 格式，不限于 hash 路由）

环境准备

1. 安装 Python

本工具基于 Python 3，需要 Python ≥ 3.8 运行环境。

  • Windows 下载地址：https://www.python.org/downloads/
  • 下载 Python 3.8+ 版本（建议最新稳定版）
  • 安装时务必勾选 "Add Python to PATH"，否则命令行无法识别 python 命令

安装完成后，打开 CMD 验证：

python --version
pip --version

2. 安装依赖库

运行前需要安装 websockets 库（≥ 10.0），用于通过 CDP WebSocket 与 Chrome 通信：

方式 A：联网安装（可上网环境）

pip install websockets

也可以使用 start-monitor.bat 自动安装（推荐方式）。

方式 B：离线安装（无外网环境）

websockets 是纯 Python 包（无 C 扩展），可通过 .whl 文件离线安装，无需编译。

步骤：

  1. 在有网络的电脑上下载 whl 文件： 
    pip download websockets -d ./pkgs
    会在 ./pkgs 目录下生成 websockets-16.0-py3-none-any.whl 文件
  2. 将整个 pkgs 文件夹通过 U 盘拷贝到内网电脑
  3. 在内网电脑上离线安装： 
    pip install --no-index --find-links=./pkgs websockets

说明：--no-index 表示不从 PyPI 联网下载，--find-links 指定本地 whl 文件所在目录。只要 .whl 文件名中含 py3-none-any，即为纯 Python 包，不需要编译环境。

依赖清单

依赖 最低版本 说明
Python 3.8 运行时（从官网下载安装）
websockets 10.0 CDP WebSocket 通信（pip install websockets）

本工具无其他第三方依赖，仅使用 Python 标准库（asyncio、subprocess、json、csv 等）。

快速开始

方式一：双击运行（推荐）

start-monitor.bat

脚本会自动安装 websockets 依赖，然后启动监控。

方式二：命令行运行

pip install websockets          # 首次需要，之后不需要
python chrome-memory-monitor.py

关于 Chrome 启动策略

  • 如果 Chrome 已以 --remote-debugging-port=9222 启动 → 自动复用，不关闭也不重启
  • 如果端口 9222 未被占用 → 自动启动新的 Chrome 实例（使用独立用户目录，不影响已有 Chrome）
  • 如果已有 Chrome 占用了端口但非调试模式 → 提示手动启动命令
  • TARGET_URL 留空时 → 不自动导航，用户在浏览器手动输入地址即可
  • TARGET_URL 非空时 → 自动新开标签页并跳转（不影响其他已有标签页）

配置文件结构

打开 chrome-memory-monitor.py，在第 33 ~ 56 行修改配置：

# ==================== 配置（可根据需要修改）====================
TARGET_URL = ""                   # 监控目标 URL（留空则不自动导航，用户在浏览器手动输入地址）
CDP_PORT = 9222
METRIC_INTERVAL = 10             # 指标数据采集间隔（秒）

# ===== 分配采样（Allocation Profile）配置 =====
SAMPLING_ENABLED = True                  # 开启/关闭分配采样
SAMPLING_INTERVAL_NORMAL = 60            # 正常模式：分配采样保存间隔（秒）
SAMPLING_INTERVAL_HIGH = 30              # 高频模式：分配采样保存间隔（秒），内存 >80% 时
SAMPLING_INTERVAL_CRIT = 5               # 紧急模式：分配采样保存间隔（秒），内存 >95% 时

# ===== 堆快照（Heap Snapshot）配置 =====
SNAPSHOT_ENABLED = True                  # 开启/关闭堆快照
SNAPSHOT_INTERVAL_NORMAL = 60            # 正常模式：堆快照间隔（分钟），默认60分钟
SNAPSHOT_INTERVAL_HIGH = 10              # 高频模式：堆快照间隔（分钟），内存 >80% 时，默认10分钟
SNAPSHOT_INTERVAL_CRIT = 5               # 紧急模式：堆快照间隔（分钟），内存 >95% 时，默认5分钟

# 阈值基于浏览器 JS 堆上限（jsHeapSizeLimit）的百分比
HIGH_PERCENT = 0.80           # 高频采样阈值：JS 堆占用超上限 80% 时加快采样
CRIT_PERCENT = 0.95           # 紧急快照阈值：JS 堆占用超上限 95% 时立即保存快照
METRIC_INTERVAL_FAST = 3        # 高频指标采集间隔（秒），超过 HIGH_PERCENT 后使用此间隔

MAX_SAMPLING_FILES = 100       # 最大保留分配采样文件数（.heapprofile），超过自动删除最旧的
MAX_SNAPSHOT_FILES = 20        # 最大保留堆快照文件数（.heapsnapshot），超过自动删除最旧的
SAMPLING_INTERVAL_US = 1000000  # 分配采样内部间隔（微秒），1000000 = 1秒

⚠️ 磁盘空间提醒：分配采样（.heapprofile）和堆快照（.heapsnapshot）会持续写入文件，堆快照单文件可达数百 MB。请确保：① 不要将脚本放在 C 盘根目录或系统盘运行；② 运行过程中留意本地磁盘剩余空间，避免磁盘写满影响系统稳定性。

参数 默认值 说明
HIGH_PERCENT 0.80（80%） JS 堆超上限 80% 时切换到高频模式
CRIT_PERCENT 0.95（95%） JS 堆超上限 95% 时切换到紧急模式
METRIC_INTERVAL_FAST 3 秒 高频/紧急模式下，指标数据采集间隔（仪表盘刷新）
MAX_SAMPLING_FILES 100 个 最大保留分配采样文件数（.heapprofile），超过自动删除最旧的
MAX_SNAPSHOT_FILES 20 个 最大保留堆快照文件数（.heapsnapshot），超过自动删除最旧的

阈值基准说明：阈值基于 performance.memory.jsHeapSizeLimit（Chrome JS 堆上限）计算。

什么是 jsHeapSizeLimit？
- 默认值（64 位 Chrome）约为 4 GB，由 V8 引擎根据可用内存自动决定
- 这是 V8 引擎允许 JS 占用的最大堆内存，高频/紧急阈值基于此上限自动计算

以默认 jsHeapSizeLimit=4096（4GB 上限）为例：
- HIGH_PERCENT=0.8 → JS 堆占用 ~3276 MB 触发高频
- CRIT_PERCENT=0.95 → JS 堆占用 ~3891 MB 触发紧急快照

首次采集到内存数据后自动计算具体 MB 值，日志会打印：
📐 JS 堆上限: 4096 MB | 高频阈值: 3276 MB (80%) | 紧急阈值: 3891 MB (95%)

自适应监控间隔详解

本工具采用三层自适应监控策略（根据内存使用率自动切换）：

正常模式（内存 < 80% 时）

指标采集：每 10 秒
分配采样保存：每 60 秒（stop→save→restart）
堆快照保存：每 30 分钟

高频模式（内存 > 80% 且 < 95% 时）

指标采集：每 3 秒（METRIC_INTERVAL_FAST）
分配采样保存：每 30 秒
堆快照保存：每 10 分钟

紧急模式（内存 > 95% 时）

指标采集：每 3 秒
分配采样保存：每 5 秒
堆快照保存：跳过（V8 全力 GC，takeHeapSnapshot 会超时或卡死浏览器）
立即触发：内存超过 95% 时，立即保存分配采样（堆快照在内存高压下不可行）

为什么紧急模式跳过堆快照？
当 JS 堆占用接近上限（> 95%）时，V8 引擎正在全力执行垃圾回收，此时调用 HeapProfiler.takeHeapSnapshot 需要遍历整个堆并暂停 JS 执行，几乎必然超时（甚至导致浏览器卡死）。分配采样（.heapprofile）相对轻量，可以在内存高压下完成。

恢复机制（滞后阈值设计）

当内存使用率降至 64%（80%×80%）以下时，
自动从高频/紧急模式恢复正常模式。

为什么不是降到80%就恢复？
- 这是"滞后阈值（Hysteresis）"，防止在80%附近频繁切换模式
- 如果80%触发高频、79%就恢复，内存小幅波动会导致：
  正常→高频→正常→高频→...（频繁抖动）
- 64% = 80%×80%，提供了16%的缓冲区，避免频繁切换

崩溃模式（Chrome 进程退出或 WebSocket 断开时）

1. 立即保存分配采样（如果已启用）
2. 立即保存堆快照（如果已启用）
3. 停止监控

分配采样分析（.heapprofile）

自动保存的 sampling-*.heapprofile 文件是 Chrome DevTools 原生支持的 Allocation Profile 格式，可直接导入分析。相比堆快照（.heapsnapshot），分配采样文件更小、采集更快，适合日常趋势分析。

分析步骤

  1. 打开 Chrome DevTools

F12 或 右键 → 检查

  1. 进入 Memory 面板

点击导航栏 "Memory" 标签

  1. 加载分配采样

点击 "Load Profile" 选择 .heapprofile 文件（Chrome 新版原生支持）

  1. 查看 Allocation 视图

加载后在 "Allocation" 视图中查看： - 按函数名分组查看内存分配来源 - 按文件/行号定位具体代码位置 - 分析 Top Down 或 Bottom Up 的调用链

提示：分配采样是统计性的，可能不会捕获所有对象，但足以定位大多数内存泄漏的根因。
文件格式变更：旧版使用 .json 扩展名，新版改为 .heapprofile（Chrome DevTools 原生支持）。

堆快照分析（.heapsnapshot）

堆快照通过 HeapProfiler.takeHeapSnapshot 按独立频率定期保存（默认每 30 分钟），同时在内存超限或浏览器崩溃时也会触发。.heapsnapshot 是 Chrome DevTools 原生格式，可用于深度分析。

技术要点：避免 HeapProfiler 域冲突

重要：HeapProfiler.startSampling 和 HeapProfiler.takeHeapSnapshot 共用 V8 Profiler 域，不能同时运行，否则会导致超时错误。
解决方案：在拍摄堆快照前，先停止分配采样（stopSampling），拍摄完成后再恢复（startSampling）。

async def take_snapshot():
    # 1. 先停止分配采样（避免 V8 Profiler 域冲突）
    await send_cdp("HeapProfiler.stopSampling")
    
    # 2. 拍摄堆快照（超时设为 60 秒）
    resp = await send_cdp("HeapProfiler.takeHeapSnapshot", {
        "reportProgress": True
    }, timeout=60)
    
    # 3. 恢复分配采样
    await send_cdp("HeapProfiler.startSampling", {
        "samplingInterval": SAMPLING_INTERVAL_US
    })

分析步骤

  1. 打开 Chrome DevTools

F12 或 右键 → 检查

  1. 进入 Memory 面板

点击导航栏 "Memory" 标签

  1. 加载堆快照

点击 "Load Profile" 或 "Load snapshot" 选择 .heapsnapshot 文件

  1. 使用 Comparison 视图分析（推荐）

加载两个不同时间点的快照 在视图下拉菜单中选择 "Comparison" 对比增量，找出增长的对象

如何定位内存泄漏

分析视图 适用场景 操作
Summary 查看各类对象的总占用 Constructor → 按 Retained Size 排序
Comparison 对比两个快照的差异 选择前一个快照，查看 delta
Containment 查看对象引用链 从 GC root 向下展开
Statistics 整体内存分布 饼图显示各类对象占比

关键指标

指标 含义 排查方向
Shallow Size 对象自身占用内存 单个对象大小
Retained Size 对象及其引用的全部对象总大小（最重要的泄漏指标） 看哪个对象 retained size 最大
Distance 到 GC Root 的距离 距离越近越难以被回收
Detached DOM 已从 DOM 树移除但仍被 JS 引用的节点 查找 "Detached" 前缀的对象

独立开关控制

分配采样和堆快照现在支持独立开关控制，可根据需要单独启用或禁用：

# 方式一：修改配置（推荐）
SAMPLING_ENABLED = True     # 开启分配采样
SNAPSHOT_ENABLED = False    # 关闭堆快照

# 方式二：在运行时动态修改（高级用法）
state = MonitorState()
state.sampling_enabled = False  # 动态关闭

开关行为

场景 行为
两者都开启 分配采样优先执行；堆快照执行前会自动暂停采样，执行后恢复
只开启采样 仅保存 sampling-*.heapprofile，不保存堆快照
只开启快照 仅保存 heap-*.heapsnapshot，不启动分配采样（无冲突风险）
两者都关闭 仅采集指标数据（JS 堆、DOM、进程内存等），不保存采样/快照文件

常见问题

Q1: 提示 "未找到 Chrome"

FileNotFoundError: 未找到 Chrome，请手动安装

解决方法：在 chrome-memory-monitor.py 第 202 ~ 207 行的 candidates 列表中添加你的 Chrome 安装路径。

Q2: 提示 "无法连接到 Chrome"

CDP 连接失败: [WinError 10061] 无法连接

可能原因：
- Chrome 被上一个实例锁定了用户数据目录
- 端口 9222 被占用

解决方法：

1. 手动关闭所有 Chrome 窗口
2. 在任务管理器确认无 chrome.exe 进程
3. 重新运行 start-monitor.bat

Q3: 脚本打开后闪退

原因：CMD 默认编码（GBK）与文件编码（UTF-8）不匹配。

解决方法：

# 方案一：先设置编码再运行
chcp 65001
start-monitor.bat

# 方案二：直接用 PowerShell 运行
powershell -ExecutionPolicy Bypass -File start-monitor.bat

Q4: 采样或堆快照文件占用大量磁盘空间

解决：分配采样和堆快照现在使用独立的保留数量控制，可根据各自的大小分别调整：

MAX_SAMPLING_FILES = 100  # 分配采样文件保留数（默认100，几MB一个）
MAX_SNAPSHOT_FILES = 20   # 堆快照文件保留数（默认20，可能数百MB一个）

分配采样文件（sampling-*.heapprofile）通常只有几 MB，远小于堆快照（heap-*.heapsnapshot 可能达数百 MB）。如果堆快照过多，关注紧急告警触发频率，或调小 MAX_SNAPSHOT_FILES。

Q5: 监控一段时间后没有生成采样文件

可能原因：
- 采样保存间隔没到（默认 60 秒）
- SAMPLING_ENABLED = False（采样被关闭了）
- Chrome 的 HeapProfiler 域未正确启用

验证：查看 monitor-YYYY-MM-DD.txt 日志，搜索 "📊" 或 "✅ 采样" 相关日志

Q6: 可以监控多个页面吗？

答：目前脚本监控的是 Chrome 中选中的第一个标签页。如果要监控其他页面，需要修改 get_pages() 函数的过滤逻辑。

Q7: 想监控已经打开的业务系统页面

答：如果 Chrome 已以 --remote-debugging-port=9222 启动，脚本会自动检测并复用。如果 Chrome 是普通模式启动的，需要用以下命令重启（或另开一个带调试端口的 Chrome）：

"C:\Program Files\Google\Chrome\Application\chrome.exe" --remote-debugging-port=9222

Q8: 采样/snapshot 文件在 DevTools 中加载报错

答：
- 采样文件（sampling-*.heapprofile）：Chrome 新版原生支持 .heapprofile 格式，直接在 Memory 面板点击 "Load Profile" 选择文件即可。如果 DevTools 无法识别，可尝试将文件名改为 profile-*.json 后重新加载。
- 堆快照文件（heap-*.heapsnapshot）：确保文件扩展名为 .heapsnapshot，使用最新版 Chrome 的 DevTools 打开。

Q9: 阈值是按系统总内存还是浏览器内存计算的？

答：目前是基于 performance.memory.jsHeapSizeLimit（Chrome JS 堆上限）计算的，而不是系统总内存。原因：

  • jsHeapSizeLimit 是 Chrome V8 引擎允许 JavaScript 占用的最大内存（64位系统通常为 4 GB）
  • 这才是浏览器实际相关的内存限制
  • 不同机器的 jsHeapSizeLimit 不同，阈值自动适配

首次采集到内存数据后，日志会打印：

📐 JS 堆上限: 4096 MB  |  高频阈值: 3276 MB (80%)  |  紧急阈值: 3891 MB (95%)

Q10: 分配采样和堆快照有什么区别？为什么需要双采集？

对比项 分配采样 堆快照
CDP 命令 HeapProfiler.startSampling→录制→stopSampling HeapProfiler.takeHeapSnapshot
运行方式 持续录制，到点 stop→save→restart 每次独立触发
文件大小 数 KB ~ 数 MB 数十 MB ~ 数百 MB
采集速度 快（毫秒级） 慢（秒级，可能阻塞浏览器）
影响浏览器性能 极小 较大（触发 GC + 遍历堆）
捕获内容 分配调用栈（统计性） 所有存活对象的完整快照
定时器 SAMPLING_INTERVAL_NORMAL（默认 60s） SNAPSHOT_INTERVAL_NORMAL（默认 60分）
DevTools 视图 Allocation / Heavy / Tree Summary / Comparison / Containment

为什么需要双采集？ 分配采样是统计性的，在极高分配频率下可能遗漏部分对象，但文件小、速度快，适合持续监控。堆快照虽然慢且文件大，但完整无遗漏。两者独立运行、相辅相成，既能保持日常监控的低开销，又能拿到最完整的数据用于深度分析。

Q11: 为什么堆快照会超时？如何解决？

原因：有两个常见原因：
1. V8 Profiler 域冲突：HeapProfiler.startSampling 和 HeapProfiler.takeHeapSnapshot 不能同时运行
2. 默认超时太短：堆快照生成可能需要几十秒，默认 15 秒超时不够

解决方案：
1. 在拍摄堆快照前，先停止分配采样（stopSampling），拍摄完成后再恢复（startSampling）
2. 将 takeHeapSnapshot 的超时时间延长到 60 秒

# 已在代码中实现：
resp = await send_cdp("HeapProfiler.takeHeapSnapshot", {
    "reportProgress": True
}, timeout=60)  # ← 超时设为 60 秒

采集策略流程

1. 脚本启动 → 关闭已有 Chrome（如有）
2. 启动新 Chrome（--remote-debugging-port=9222）→ 先打开 about:blank
3. CDP WebSocket 连接 → 启用域（Performance/Memory/HeapProfiler）
4. 通用导航：通过 window.location.href 跳转到目标 URL
5. 启动分配采样（HeapProfiler.startSampling）→ 开始持续录制
6. 循环（三个独立定时器互不干扰）：
   ├─ 指标采集定时器（每 METRIC_INTERVAL 秒）：
   │    collect_metrics() → 写 CSV → 渲染仪表盘（含 Sparkline）
   ├─ [分配采样定时器] 每 SAMPLING_INTERVAL_XXX 秒：
   │    stopSampling（停止录制）→ 保存 .heapprofile → startSampling（继续录制）
   └─ [堆快照定时器] 每 SNAPSHOT_INTERVAL_XXX 秒：
         stopSampling（避免冲突）→ takeHeapSnapshot → 保存 .heapsnapshot → startSampling
7. 内存超限时：立即触发分配采样保存 + 堆快照保存（比定时提前）
8.  Chrome 崩溃 → WebSocket 断开 → 保存最后采样+快照 → 退出

退出方式

方式 操作
正常退出 在 CMD 窗口按 Ctrl + C
自动退出 Chrome 进程崩溃或退出时自动停止

注意：脚本退出后 不会关闭 Chrome 浏览器，用户数据目录（.chrome-debug-profile）会保留以便下次复用。
